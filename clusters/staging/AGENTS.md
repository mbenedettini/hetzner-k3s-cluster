# Staging Cluster Guidance

This directory is the Flux entry point for the live cluster. The `staging`
name is historical and does not imply that changes are non-production.

## Reconciliation Model

- `flux-system/gotk-sync.yaml` points Flux at `main` and `clusters/staging`.
- `apps.yaml` reconciles `apps/staging`.
- `infrastructure.yaml` reconciles controllers, configs, and add-ons.
- `secrets.yaml` reconciles cluster-level encrypted secrets.
- These Flux Kustomizations prune resources. Treat path changes, removals, and
  resource renames as destructive operations requiring dependency review.

The explicitly encoded infrastructure dependency is:

```text
infra-controllers -> infra-configs
```

`infra-addons`, `apps`, and `secrets` do not currently declare cross-
Kustomization dependencies. Do not describe logical ordering as guaranteed
unless it is represented by `dependsOn`.

## Cluster-Specific Configuration

- Put environment-specific patches here rather than modifying reusable
  manifests solely for this cluster.
- Current patches configure the production Let's Encrypt endpoint and email and
  reduce Istio control-plane resource usage for the small node.
- SOPS decryption expects a `sops-gpg` Secret in `flux-system`; provisioning the
  private key is intentionally outside this repository.
- `.sops.pub.asc` contains public recipient material only. Never place a private
  key in this directory.

## Generated Bootstrap Files

- `flux-system/gotk-components.yaml` and `gotk-sync.yaml` are generated by Flux.
  Do not hand-edit them or guess a regeneration command.
- Review generated-file changes separately from authored cluster configuration.

After changing this directory, validate the cluster entry-point YAML and every
downstream Kustomize tree affected by its paths or patches with
`./scripts/validate.sh`.
